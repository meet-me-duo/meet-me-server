## Agreed data and behavior boundaries

The optional diagnostic sidecar records bounded enum causes/reset codes, relative event times, configured timeout facts, observed cancellation state and explicit incomplete/truncation flags. It records no original input, request/response body, header value, key, URL, exception message or exception class name. An observed HTTP/2 CANCEL and a canceled flag do not identify the responsible peer or prove the failure cause. Unknown evidence stays unknown. Existing observation DTO/database fields remain unchanged; optional diagnostics cannot alter the provider result, request budget or failure classification.

The experiment's durable limit is ten conservative physical-admission reservations across phases/process reopenings, with emitted headers reported separately. A fresh SDK Call has a fresh physical UUID even if its attempt is reused. One UUID contributes at most one normalized failure. Typed parser evidence replaces weaker HTTP/transport evidence; HTTP503 must not become NETWORK merely because transport used IOException. Equal-rank contradictory typed evidence, missing coverage and counter failure stop conservatively. Two distinct physical calls with the same normalized code stop globally, across providers. Connectivity is at most two diagnostic attempts; the second failure ends it even with a different code. Completed connectivity permits one E2E room. Multiple legitimate execution IDs in that current room remain valid; an earlier room's worker remains denied.
