# 실제16 원인 분석과 수정 경계

이번 결과에서 전송 누락이나 라벨 반전이 원인이라는 근거는 없다. 실제16건 모두 원문과 reference_at·time_zone·locale·search_start_date·search_end_date, 고정 instructions와 세 선택지, 사전 wire·응답 SHA가 일치한다. 원문과5문맥이 총6 input 필드이며 자동 원문 변환은 확인되지 않았다. 실제 client network interceptor도16건을 관측했다. 다만 공급자 내부가 어떤 부분을 활용했는지, 토큰화·attention·판단 이유는 응답에 없어 확인할 수 없다.

프롬프트가 없거나 전혀 엉뚱했던 것은 아니다. 현재 지시는 material ambiguity, 부정·예외·범위·자기모순, 날짜 문맥, 넓은 범위와 유효한 의존 조건 보호를 이미 포함한다. 개선 여지는 **조건이 어느 날짜·장소·시간·대상에 적용되는지 연결이 완결됐는가**를 더 구체적으로 판별시키는 데 있다. 이러한 task/prompt 적합성, 작은 분류 모델의 관계 처리, 제공 문맥의 범위와 confidence 정책이 가능한 기여 요인이지만, 현재 출력만으로 프롬프트 하나를 원인으로 확정하거나 수정 효과를 약속할 수 없다.

raw false CLEAR6건은 날짜·시간·장소·지시대상·의존 조건·유연 조건 적용범위에 각1건씩이다. 일정 관점으로 묶으면 시간 해석2, 장소 해소1, 지시/의존 연결2, 유연 조건 적용대상1이다. 모두 gold NEEDS_REVIEW8건 중 발생했고, 원래 miss6/8과 사전 raw gateFAIL을 유지한다.

실제 대표를 원문 없이 추상화하면 첫째, 두 후보 장소마다 서로 다른 가능 시간이 있는데 어느 장소가 어느 시간인지 연결이 빠졌다. 이는 장소를 넓게 허용한 것이 문제가 아니라 일정 교집합을 바꾸는 배정이 미정인 것이다. 둘째, 두 날짜 중 하나는 오후로 제한하고 다른 하나는 넓게 허용하지만 제한이 어느 날짜에 적용되는지 미정이다. 이때 필요한 질문은 적용 날짜이며 넓게 허용한 시간을 더 좁히는 질문이 아니다. reference/timezone/search 범위만으로 이러한 개인 의도를 채울 수 없다. 모델이 유효한 의존/넓음 보호를 과도하게 적용했을 가능성은 가설로 남긴다.

명확한 gold에서 B로 간5건은 날짜·지시대상·의존·부정·예외 각1건이다. 이 중4건은 raw CLEAR가 맞았으나 기존 .8 정책이 LOW_CONFIDENCE로 유보했고, 1건은 raw NEEDS_REVIEW 오탐에 LOW_CONFIDENCE가 동반됐다. 실제 대표 중 하나는 명시한 후보 날짜와 요일·연도 문맥으로 날짜가 유일하게 결정되는 경우다. 다른 하나는 같은 가능 조건을 동일한 의미로 다시 말했을 뿐 새로운 미정 조건이 없는 경우다. 후자는 부정의 대상/범위와 실제 충돌을 구분하지 못했을 가능성이 있다. 낮은 confidence가 왜 나왔는지는 관측되지 않았다.

공식계약 독립 검토는 choice/probabilities와 별도 confidence를 구분한다. confidence를 CLEAR 확률이나 보정된 정답 확률로 해석할 근거가 없으며 .8은 기존 앱 진단 기준이다. 6raw miss와5과잉 B는 gold가 다른 별개 사례로 교집합0, 합집합11/16이고 같은 대조쌍을 공유하는 수는3/8이다. 전달된6필드가 완전하다는 사실과 실제 모임 문맥 설계가 충분하다는 판단도 다르다. 실제 MeetingRoom에는 purpose와 mode가 있지만 현재 A에는 전달하지 않는다. 모임 목적/방식이 도움이 될 여지는 있어도 이번 봉인16에 그 값이 원래 없어 사후에 임의 목적을 붙여 gold를 고칠 수 없다. 현재 room 도메인에서 도시나 기본 AM/PM을 확인하지 못했으므로 timezone을 도시·오후 의도로 대체하지 않는다. purpose/mode 추가는 명시적인 context·privacy·입력 상한·wire hash 계약으로 별도 검토한다. 타인의 원문·질문·답변을 붙여 모호성을 푸는 안은 포함하지 않는다.

사전 gold는 독립 검토된 원래 unknown facts와 must-preserve 조건을 유지한다. 새로 확정된 gold 결함은 없으며, 모델과의 불일치만으로 oracle을 무효화하지 않는다. 날짜 숫자와 요일 중 무엇을 우선할지 정하지 않은 충돌을 자동으로 수리하거나, 장소가 불명확할 때 도시를 추정하는 정책은 승인되지 않았다.
