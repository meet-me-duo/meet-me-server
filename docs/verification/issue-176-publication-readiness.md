## 구현 목적과 준비 검사

- 개인 입력은 원문과 보완 답변·revision·기준 시각을 함께 보존한다. Jev는 보완 필요 여부를 돕는 분류기이고, 개인 Luna는 불필요 통과 또는 구조화된 질문을 제공한다. 질문은 한 번이며 기술 실패나 미해결 의미를 CLEAR로 위장하지 않는다.
- 최종 분석은 모든 접수 근거를 읽고 해석 불가 입력을 이유와 함께 분리한다. 시간 교집합·추천·확정은 서버의 결정론 규칙을 유지한다.
- 검증하지 못한 장소·이동 조건은 실제 충돌과 구분한다. 시간 후보의 기존 설명과 확정 재조회에 미확인 사실을 유지하며 자동 비대면 전환·가짜 장소·출발지·이동시간 추정은 추가하지 않는다.
- V22 SQL과 publisher·승인 reader·호스트 reader의 목록, 역사 호환·checksum·누락/미지 이력 거절을 연결한다. 기존 Node gate 실패를 숨기지 않는다.
- V21/V22 신규·기존 데이터와 reader/writer, 격리 PostgreSQL의 DDL 잠금·취소·트랜잭션 복구를 검증한다. 실제 운영 부하·복귀 검증과 동일시하지 않는다.
- 웹은 기본 E2E와 native 하네스를 명시적으로 분리하고 최신 디자인·모바일·운영자 진입을 보존한다. API·초안 소유권·답변·후보·확정·새로고침의 최종 통합 검증을 수행한다.

새 게시 준비에서는 유료 모델·지도 요청이 없다. 과거 유료 실행의 남은 호출 한도를 재사용하지 않는다. 저장 응답 재생의 usage는 새 토큰 사용량이나 청구액이 아니다. 과거 60초 단독 Luna 진단이 33.296초에 성공한 기록도 앱의 27초 정책 변경이나 전체 통합 성공으로 확대하지 않는다.

## DB·출시 전 제한

V21은 nullable 입력 근거와 protocol/status 허용값을 추가하고, V22는 참여자별 장소 미확인 사실과 불변 guard를 보존한다. 기존 행의 `place_unverified=false`에서 유도되는 `attendance_confirmed=true`는 과거 표시 호환이며 새 장소 검증이 아니다. 새 서버가 새 열을 직접 읽으므로 schema-before-code가 필요하다.

V2 생성 설정 OFF만으로 공통 조건부 후보 계산까지 꺼지지는 않는다. 구 서버·구 웹은 새 상태를 이해하지 못할 수 있다. 운영 적용 전에는 하위 호환 웹, catalog/호스트 reader·DB·서버 전환, 이미 새 데이터가 생긴 뒤의 복귀·roll-forward 순서를 별도 승인·검증해야 한다. down migration이나 과거 자료 삭제를 안전한 롤백으로 취급하지 않는다.

질문 한도의 적용 범위, 미응답·검사 중·기술 실패·이전 접수본, 공개 고지의 운영 세부 정책은 기존 실험 가정/TBD와 구분한다. 이번 준비가 이를 자동 확정하지 않는다.

## 공개 자료 경계와 최종 결과 기입

공개본에는 검토한 코드·계약·검증 요약만 담는다. 원본 모델 응답·질문 본문·원본 로그·transport dump·키·토큰·헤더·개인정보·봉인 fixture/gold·로컬 DB/백업은 제외한다. `local-only-evidence/` 표기는 비공개 로컬 보존 자료의 이름이며 저장소의 다운로드 경로나 재현 명령이 아니다. 패턴 검색만으로 비밀·개인정보 부재를 보증하지 않는다.

현재 준비 단계의 최종 commit SHA, 전체 무료 검사, 독립 검토, Draft PR URL 및 그 SHA의 CI 결과는 실제 완료 뒤 이 절에 기록한다. 실패·미실행은 그대로 남기며 CI green이어도 병합·배포·V2 활성화는 수행하지 않는다.

## 공개 CI 독립 실행을 위한 하네스 정리

초기 통합 소스 전체 검사는 2,670개 중 2,625 PASS / 28 FAIL / 기존 SKIP 17이었다. 실패는 5개 실험 budget/preflight 클래스에 집중됐다. 공개용 합성 승인 ID의 문법을 원래 검증 형식과 다르게 바꾼 준비 오류를 바로잡아, 검증 문법·claim·상한을 유지하면서 실제 대화 ID와 다른 합성값만 사용한다. 과거 실행의 실제 승인·해시를 새 실행 권한으로 재사용하지 않는다.

기본 사전검사는 개인 Cloud의 과거 manifest builder/시나리오 경로를 호출하지 않고 임시 디렉터리의 독립 합성 Git source·불투명 데이터만 검증한다. 소스 누락·해시 변조·revision·승인·중복 경로·기존 출력·옛 호출 상한의 거절과 claim/파일 불변 검사를 유지·확장했다. validationRoot의 기본값과 실제 유료 load 본문·claim·cap은 유지한다.

기본 응답 replay 역시 실제 모델 응답이나 과거 DB를 읽지 않고 독립 합성 3명·2일·6개 시간 구간·이동 제약 2개·답변 1개를 사용한다. 원래 input_ref 이외 정보가 바뀌지 않는지와 실제 JDBC source fence→원래 adapter→worker/DB→추천·확정·미확인 보존을 검증한다. 과거 artifact replay는 명시적 LOCAL_ARTIFACT opt-in으로만 남겼으며 이번 최종 준비에서 그 모드를 실행하지 않는다. 기본 검사를 삭제하거나 새 skip으로 대체하지 않았다.

합성 원문의 교집합은 12월 3일 KST19:30–21:00, 12월 4일 KST20:00–21:30이다. 개인 답변에 명시된 시작 시각만 반영하고 타인의 조건으로 개인 사실을 추측하지 않는다. 미검증 이동 조건은 대면 참여를 확정하지 않으며 비대면 허용 여부는 방 모드를 따른다. 이 데이터는 제공자 응답·블라인드 gold에서 복사하지 않은 공개 합성 계약 예시다.

출력만 남기는 무료 fixture 세 곳은 JDK 임시 디렉터리를 사용한다. 명시적 유료 실행의 고정 경로와 요청 예산을 바꾸지 않는다. 예산·사전검사·DDL 집중45개와 린트, 합성 replay/무료 앱 경로7개의 기능 검사를 통과했고, 두 후속 파일은 서식만 정리했다. 최종 전체 결과는 현재 실행이 끝난 뒤 별도로 기록한다.

기존 배포 회귀에서는 현재 V20으로 고정한 OA01 fixture를 V21/V22까지 확장했다. 과거 V1–V20의 고정 SHA와 역사 거절 조건은 유지했고 집중 publication2개가 통과했다. 초기 전체 Python의 3 FAIL / 1 ERROR와 Node395개 중392 PASS / 3 FAIL은 보존한다. 15초/20초 하네스 시간 오류는 제한·단언을 바꾸지 않은 집중 재실행에서 Python1개·Node3개·refresh shell이 통과했으며, 최초 오류 원인을 부하로 확정하지 않는다.

이 관리형 환경의 Nginx smoke는 원본 config 파일 mode600/제한된 container capability에서 읽기 거부됐고, byte-identical/readable 복사본에서도 로컬 health 성공을 확인하지 못했다. Nginx/제품 보안/시간 제한 소스는 변경하지 않았다. 공개 checkout의 같은 원본 검사 결과는 해당 최종 SHA의 CI에서 확인하며, 로컬 실패를 통과로 표시하지 않는다.
