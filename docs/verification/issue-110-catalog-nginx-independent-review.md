# Issue #110 catalog and Nginx independent source review

Review scope: `approved_release.py`, `publish_manifest.py`, `host-approved-release.py`, Nginx configuration and CI wiring after the sparse-catalog implementation. The reviewer authored the separate contract tests and performed this source/evidence review without executing tests, modifying product code, accessing production or touching shared Docker processes.

## Finding and verified resolution

**P2 — migration directory symlink is followed by the publisher.** `build_manifest` enumerates `root / src/main/resources/db/migration`, but only checks whether each leaf migration is a symlink. If the migration directory itself is a symlink to another directory containing the exact thirteen ordinary files, every leaf `is_file()` is true and `is_symlink()` is false. The manifest is produced from that external tree. The deploy publication workflow copies `src/main/resources/db/migration/*.sql` into `deploy/migrations/`, losing the directory-link provenance before tar validation, so later archive symlink rejection does not cover this case. This contradicts the explicit source-symlink default-deny boundary. The existing new test exercises leaf migration/guard links only. Reject symlinked migration-directory/within-repository ancestors without following them, and add an independent directory-link regression before claiming this boundary complete. This was identified by source inspection, not an executed exploit or test.

**Closed after independent regressions and source review.** Four new cases retain valid ordinary leaf files while linking the migration directory, `src/main`, `deploy/pipeline` or repository root. The full pre-fix Linux run reports 17 cases, with exactly these four failing `ERR_ASSERTION` because the publisher incorrectly returned `ok: true`; all other thirteen pass. That is valid RED. The earlier pattern-filtered attempt reports only a file-level one-case PASS and matches no intended cases; it is explicitly excluded as RED evidence. The implementation now uses `source_path` to reject the repository root and each within-repository path ancestor if linked, before reading migration or guard bytes. Final Linux execution passes all four regressions. This closes the P2 finding. No additional P1/P2 source issue was found in this review.
