## Nginx verification requirement

The existing JSON access log uses `$uri`, which omits callback query arguments. The current generic `error_log /dev/stderr warn` may include the complete request line after upstream failure, exposing OAuth code/state. A native Nginx negative control must provoke a refused/reset upstream and prove both synthetic query markers appear before the fix and disappear afterwards. Location-only suppression covers routed callback failures; request parsing errors may occur before location selection and therefore require separate consideration. Native checks must preserve the effective proxy/access-log configuration, use isolated fixture resources, and leave production untouched.
