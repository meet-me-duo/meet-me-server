# 원문·보완 근거를 보존하는 V2 실험

기준 소스는 main `40aea5139525b9ed2cba34428f0072cc42e15820`이다. 사용자 승인은 별도 피처에서 구현·격리 테스트·유한한 실제 모델 평가·보고까지다. main/develop 병합, 운영 배포·DB·방 사용, 자격증명/권한 확대는 포함하지 않는다. 웹 피처는 사용자의 직접 확인과 후속 승인 전 develop에 병합하지 않는다.

## 설계 우선순위

Jev는 보완 질문 필요 여부를 돕는 보조 장치이며 완벽한 모호성 검출·불확실성 사전 차단이 목표가 아니다. 전체 입력과 보완 근거를 모아 수행하는 최종 분석을 중심에 둔다. Jev의 완벽성을 이유로 과도한 상태·임계값·반복 검사·차단 조건을 추가하지 않는다. 검증은 Jev 단독 판정뿐 아니라 질문의 유용성과 최종 분석까지의 진행·안전한 미반영 처리를 함께 평가한다. 이 우선순위는 기존 기술 오류를 정상 판단으로 바꾸거나 현재 승인된 분기를 추가 변경하는 뜻이 아니다.

## Jev·Luna·최종 분석의 역할

- Jev는 개인 입력에 보완 질문이 필요한지 판단을 돕는 단순 분류기다. 완전한 시간 구조화·교집합 계산·최종 분석 성공을 확정하지 않는다.
- 개인 Luna는 재확인 결과 보완이 불필요하면 CLEAR로 넘기고, 필요하면 Structured Output으로 구체적인 질문과 안전한 선택지/직접 답변 경로를 제공한다. Jev가 재확인 대상으로 보냈다고 질문을 반드시 만들지 않는다.
- 사전 확인의 목적은 최종 분석 불가로 끝날 위험을 줄이는 것이다. 각 참여자의 입력이 모인 뒤 해석이 더 쉬워질 수 있으므로, 앞단에서 모든 사실을 확정하려고 전체 맥락 해석의 기회를 없애지 않는다. 원문과 보완 근거는 그대로 최종 분석에 제공한다.
- 최종 모델은 전체 입력의 맥락을 해석하되 다른 사람의 가능 시간으로 개인만 아는 사실을 발명하지 않는다. 끝내 해석하지 못한 입력은 기존대로 안전하게 제외하고, 주최자에게 후보와 함께 제외 입력·사유를 보여준다. 시간 후보 계산과 선택 저장은 기존 서버 계약을 따른다.

현재 승인된 라벨 중심 분기는 이 목적과 맞는다. 첫 CLEAR는 개인 보완 없이 접수하고 NEEDS_REVIEW/INDETERMINATE는 Luna가 재확인한다. 답변 후에는 추가 질문 없이 미해결 근거까지 최종 분석으로 보낸다. 내부 CLEAR/CONFIRMED는 개인 보완 단계의 상태이며 완전한 시간 해석·최종 구조화 성공을 보장하는 관문으로 해석하지 않는다. 이 일치 확인은 구현 목적의 대조이며 실모델 전체 흐름 성공을 새로 검증한 것은 아니다.

## 적용 경계

`meetme.precheck.evidence-enabled` 기본값은 false다. true인 인스턴스에서 새로 만든 방에만 `PRE_SUBMIT_V2`를 기록한다. 기존 LEGACY/V1 방과 기존 비공개 원문 정책은 유지한다. V21은 nullable JSONB 열과 상태 허용값만 추가하며 과거 제출을 재해석하거나 원문을 소급 공개하지 않는다. 기존 provider/routing/classifier 활성화와 기술적 전송 보호는 별개다.

## 합의한 제품 방향과 현재 실험 구현

- Jev는 시간 보완 필요 여부를 판단하는 보조장치다. 문맥과 명시 시간 규칙으로 조건을 바꾸지 않고 구간을 표현할 수 있으면 넓은 범위도 유효하다. 장소 불명확성만으로 시간 제출을 막지 않는다.
- 2026-10-30 승인된 ADR-065에 따라 유효한 Jev Choice 라벨로 분기한다. 최초 CLEAR는 확정 접수하고 NEEDS_REVIEW·INDETERMINATE는 Luna가 재확인해 CLEAR 또는 구체적인 질문을 반환한다. confidence·선택지별 확률은 결과 객체와 기존 실험 관측에 보존하며 낮은 값·동점이 V2의 의미 라벨을 바꾸지 않는다. 기술 실패를 정상 판단과 구분하고 답변 뒤에는 추가 Luna 질문을 생성하지 않는다.
- Luna는 보완이 불필요하면 통과시킬 수 있다. 구체적인 질문과 안전한 A/B+직접 답변 또는 질문+직접 답변만 제공한다. 선택지는 질문 대상의 답변이며 전체 원문을 대체하지 않는다. ‘둘 다 아님’은 추가하지 않는다.
- 원문, 원문 revision/기준 시각, 질문 대상 코드포인트 위치·구절, 질문, 명시 답변, 선택 ID, 답변 시각/기준 시각을 하나의 불변 근거로 보존한다. 원문 수정은 과거 답변을 새 원문에 자동 적용하지 않는다.
- 답변 후에도 불확실하면 `RECEIVED`이며 `CLEAR`로 표시하지 않는다. 접수 버전은 최종 전체 해석에 포함한다. 전체 문맥이 정당하게 해소하지 못한 입력은 미반영 사유로 남기고 다른 입력의 후보 계산은 계속한다. 다른 사람의 가능 시간으로 본인만 아는 사실을 추측하지 않는다.
- 최종 모델은 자연어를 기존 구조화 조건으로 바꾼다. 교집합·참석자·점수·추천 및 주최자 선택은 기존 서버 계산을 유지한다. 최종 조건과 원문/답변 근거는 같은 submission version ID로 연결한다. 임의 5/10분 양자화는 도입하지 않는다.
- 시간 규칙은 오전00~12/오후12~24, 날짜 없는 요일은 방 검색 기간 전체, 19시 이후는 당일24시까지, 22시~새벽2시는 다음날02시까지다. 아침/저녁/밤의 독립적인 경계는 정하지 않는다. 시간/장소 결합을 독립 조건의 임의 조합으로 바꾸지 않는다.

## 실험 가정과 배포 전 결정

Jev는 Choice 세 라벨을 유지한다. V2 라우터는 검증된 `semanticAssessment`를 우선하고 공통 port가 이를 제공하지 않으면 `assessment`를 사용한다. 최초 CLEAR는 확정 접수, 나머지 두 라벨은 Luna 재확인 대상이다. 이미 보완 답변이 있으면 CLEAR만 해석 확정하고 NEEDS_REVIEW·INDETERMINATE는 추가 생성 없이 미해결 근거와 함께 접수한다. V2는 confidence 동작 기준값을 요구하지 않으며 기본값 null도 유효 라벨의 분기를 막지 않는다. 응답 confidence의 필수성·유한수/범위·확률 분포·라벨/최댓값·파생 confidence 일관성, 명시된 잘못된 구성값, HTTP·기술 실패 검증은 유지한다. 원래 V1의 confidence 정규화와 기준값 검사는 바꾸지 않는다.

이 결정은 초기 실험에서 저신뢰 라벨을 INDETERMINATE로 바꾸고 Luna를 생략하던 우선순위를 대체한다. 과거0.8 평가·기존 ADR과의 차이는 [당시 분기 대조](verification/experimental-jev-routing-policy-audit.md)에 보존한다. 운영의 V1 confidence 값·보정과 V2 라벨의 실제 의미 품질은 별도 미검증이며, 이번 승인은 무료 격리 구현에 한정된다. 새 DB 열이나 공개 API를 추가해 confidence를 영구 저장하는 변경은 하지 않고 현재 결과 필드·실험 관측을 보존한다.

질문 한 번의 적용 범위는 방·참여자당으로 가정한다. 원문 수정/취소/재시도는 이를 초기화하지 않는다. 질문 미응답·검사 중·전송 기술 실패는 기존처럼 새 접수 버전을 만들지 않으며, 이전 접수 버전이 있으면 마감에 그 버전을 사용한다. 한도를 사용한 뒤 새 원문이 다시 질문을 필요로 하면 `UNRESOLVED`로 남기고 이전 접수본을 유지한다. 이는 질문 한 번 뒤 답변한 현재 버전의 `RECEIVED`와 다르다. 이 세부 정책은 사용자 최종 결정이 필요하다.

직접 답변의 상대 날짜 기준은 답변 시각, A/B는 원문 기준을 사용한다. 원문 자체의 기준 시각은 답변 때문에 이동하지 않는다. 원문+답변 합계는 기존 개인500/방10000 코드포인트 한도를 유지한다. 한도 확대나 아침/저녁/밤의 경계 선정은 이번 실험에서 확정하지 않는다.

새 V2 웹은 제출 전에 최종 해석에 반영되지 않은 원문과 확정 보완 답변이 주최자에게 보일 수 있음을 고지한다. 주최자 진단은 최종 원문·답변·사유/실패 범위이며 중간 질문 이력은 제외한다. 일반 참여자는 해당 진단을 조회할 수 없다. 후보 시간에 참석하지 못한 사람과 해석 실패 입력을 구분한다. 고지 및 최종 공개 범위는 운영 전 확인 대상으로 남긴다.

## 영속성·경합·호출 검증

후보와 submission version의 `input_evidence`를 별도 보존한다. 접수 시 해석 상태가 확정된 근거를 version INSERT에 포함하고 제출 head를 갱신한다. 마감은 기존대로 정확한 version ID를 동결하며 최신 candidate나 이후 수정으로 대체하지 않는다. 재시도/답변 멱등 키, candidate revision/check version CAS, room lock, owner binding, deadline 검증을 유지한다. 마감 후 수정은 새 원문에 `POST_CLOSE_REVISION` 미확정 근거를 만들며 이전 답변을 복사하지 않는다.

개인 source 해시는 원문과 전체 근거를 포함한다. 최종 source 해시는 동결 version 근거를 포함하며 pending candidate의 근거로 검증하지 않는다. V1 null 근거의 기존 해시를 보존한다. 입력 길이·바이트 상한과 최종 출력 validator를 유지한다. 조건을 해석하지 못한 한 항목을 성공으로 위장하지 않고 안전하게 제외한다. 최종 응답이 다시 질문하면서 제시한 조건은 적용하지 않는다.

## 검증과 한계

독립 테스트 설계자의 RED→GREEN, 실제 PostgreSQL/HTTP, source fencing, CAS·소유권, 마감·수정, 최종 미반영 공개, 결함 주입과 전체 회귀를 구분해 기록한다. 실제 앱 테스트의 합성 로컬 RSA 계정은 실제 OAuth 인증 검증이 아니다. mock/합성 모델 결과는 실제 모델 품질을 입증하지 않는다.

새 블라인드 작성자는 서비스 사용자 설명만 받아 개발2모임(6명), 봉인2모임(8명)의 입력·의도·답변·정답을 결과 전에 고정했다. 구현자는 봉인 개별 정답을 열지 않는다. 과거40+개 블라인드 전체 자료를 확보했다고 주장하지 않으며 기존 노출된 연구·미실행 평가 자산을 새 holdout으로 재사용하지 않는다.

모델 평가는 개발 smoke부터 순차로 한 번씩 실행한다. 개발 상한은 `Q=12,R=2,2Q+5R=34`, 봉인 상한은 `Q=16,R=2,2Q+5R=42` 물리 호출이다. 같은 입력이 성공할 때까지 반복하지 않는다. 과거 평가의 threshold0.8은 고정 실험 설정이며 검증된 운영 기준값이 아니다. ADR-065 이후 V2에서는 라벨 분기에 쓰지 않으며 과거 실행 결과·manifest를 새 정책의 검증 증거로 재해석하지 않는다. 실행 소스/설정/입력 해시, 단계별 실제 전송 관측·토큰 사용량·미실행 단계를 함께 보고한다. 관측 토큰은 청구서나 확정 비용이 아니다.

최종 모델 입력은 표시 이름 매핑·주최자의 방 목적 전체를 제공하지 않는 기존 계약을 유지한다. 이름 참조나 개인 사실이 이를 필요로 하면 문맥만으로 해소할 수 없으며 임의 추측으로 통과시키지 않는다. A/B의 의미 보존도 구조 validator만으로 증명되지 않아 실제 모델 평가를 별도로 수행한다.

## 롤백

운영 반영은 승인되지 않았다. 실험 인스턴스를 중단하고 설정을 false로 돌리면 이후 새 방은 기존 V1이다. 이미 생성한 V2 방은 V2 reader가 필요하므로 V21 데이터가 있는 상태에서 구 binary로 조용히 되돌리지 않는다. 운영 적용 시에는 additive migration 유지와 V2 writer 중단·reader 유지 순서를 별도 검증해야 한다. 격리 합성 DB/컨테이너는 평가 결과를 파일로 보존한 뒤 제거할 수 있다.


## 2026-10-31 장소 미검증 시간 후보 (ADR-066)

이 격리 작업은 최종 구조화 원문·보완 답변·미해결 근거를 변경하지 않고 서버의 후보 단계만 확장한다. 알려진 장소 충돌과 시간 충돌은 유지하며, 처리하지 못한 장소·이동 조건은 시간 후보 설명 안에 미확인으로 담는다. 미확인 참여자별 상태는 V22의 candidate/recommendation 관계에 보존하고 주최자 확정 후에도 남긴다. 공개 API의 attendance_confirmed=false는 시간 일치 인원과 실제 참석 확정의 차이를 나타낸다. 새 경고 영역·개인 원문 공개·온라인 자동 전환은 추가하지 않는다. 사용자의 최신 승인에 따른 로컬 구현이며 운영/배포/병합·유료 재평가는 승인 범위 밖이다. [검증 보고서](verification/experimental-conditional-place-candidates-result.md)를 따른다.
