# User Intervention Rules

## 목적

외부 계정, 권한, 결제, 법적 동의와 비밀정보가 관련된 작업은 에이전트가 수행할 저장소 작업과 사용자가 직접 수행할 작업을 명확히 분리한다. 사용자 개입이 필요하다는 사실을 늦게 발견하거나, 비밀값을 채팅·명령 출력·로그·저장소에 노출해서는 안 된다.

## 책임 표기

- `[AGENT]`: 에이전트가 저장소와 허용된 도구 안에서 독립적으로 완료할 수 있는 작업
- `[USER]`: 사용자 신원, 소유권, 동의, 결제, 관리자 권한 또는 실제 비밀값이 필요하여 사용자가 직접 완료해야 하는 작업
- `[SHARED]`: 에이전트가 코드·설정·절차를 준비한 뒤 사용자가 외부 시스템에서 완료해야 하는 작업

작업에 두 책임이 섞여 있으면 하나의 완료 항목으로 뭉치지 말고 `[AGENT]`와 `[USER]` 하위 작업으로 분리한다. `implementation_plan.md`와 작업 보고에서도 같은 표기를 사용한다.

## 사용자가 직접 수행해야 하는 작업

다음 작업은 기본적으로 `[USER]`다.

- Google AI Studio/Google Cloud, Kakao Developers, GitHub, AWS 등 외부 서비스의 계정 생성과 로그인
- SSO, MFA, CAPTCHA, 이메일·전화 인증과 조직 초대 수락
- 이용약관, 개인정보 처리, OAuth 동의 화면, 앱 검수와 브랜드 검증에 대한 승인
- 결제 수단 등록, 유료 플랜 선택, 예산·할당량 상향과 비용 발생 승인
- 프로젝트·조직·계정 소유권 선택과 관리자 권한 부여
- Gemini API Key, OAuth Client Secret, AWS Access Key 등 실제 비밀정보의 생성·회전·폐기
- 실제 비밀값을 GitHub Actions Secrets, 배포 환경 또는 비밀관리 서비스에 입력하는 작업
- OAuth Redirect URI, 도메인 소유권과 운영 콜백 URL의 최종 승인
- GitHub Environment 보호 승인, 브랜치 보호나 조직 정책처럼 관리자 권한이 필요한 설정의 최종 적용
- 운영 배포, DNS 변경 또는 외부 사용자에게 영향을 주는 비가역적·고위험 작업의 최종 승인

사용자가 명시적으로 자동화를 요청하고 안전한 인증 도구가 준비된 경우에도 비밀값 노출, 결제, 법적 동의, MFA와 최종 운영 승인은 사용자가 담당한다.

## 에이전트가 수행하는 작업

다음 작업은 기본적으로 `[AGENT]`다.

- 외부 연동의 선택지, 제약, 비용과 트레이드오프 조사 및 제시
- 포트·어댑터, DTO, 실패 경계와 테스트 설계 및 구현
- `.env.example`, 설정 프로퍼티, GitHub Actions 워크플로와 Terraform 변수 선언에 비밀값 없는 placeholder 추가
- 필요한 secret 이름, OAuth scope, Redirect URI 후보와 최소 권한 목록 정리
- Mock/Fake/Testcontainer를 사용한 비밀정보 없는 로컬·자동 테스트
- 사용자가 외부 시스템에서 수행할 정확한 단계, 입력 위치와 완료 기준 안내
- 도구가 허용하면 secret의 실제 값이 아닌 존재 여부, 이름, 수정 시각과 연결 상태만 검증
- 사용자 작업과 독립적인 저장소 작업을 계속 진행하고 차단 범위를 최소화

## 사용자 알림과 행동 가이드 의무

사용자 개입이 필요하다고 판단하면 종속 구현이나 실패하는 시도를 반복하기 전에 즉시 다음 형식으로 알린다.

```text
[USER ACTION REQUIRED]
이유: 왜 사용자 신원·권한·동의 또는 비밀값이 필요한지
위치: 접속할 서비스 URL과 메뉴 경로 또는 실행할 명령
사전 조건: 필요한 계정, 권한, 프로젝트와 준비물
할 일: 번호가 있는 단계별 최소 행동
입력값: 입력할 설정 이름, 형식과 안전한 예시
선택지: 사용자가 결정해야 하면 각 선택지와 트레이드오프
공유 금지: 채팅이나 저장소에 붙여 넣으면 안 되는 실제 값
완료 확인: 사용자가 확인할 화면·상태와 에이전트에게 알려줄 비밀값 없는 완료 신호
다음 검증: 완료 후 에이전트가 수행할 검증
영향 범위: 이 작업 때문에 막힌 항목과 계속 진행 가능한 항목
```

- 사용자가 그대로 따라 할 수 있도록 서비스와 메뉴 명칭을 현재 공식 UI 기준으로 확인하고 단계별로 안내한다.
- 콘솔 UI가 변경되었거나 계정 유형에 따라 경로가 다르면 추측하지 않고 차이를 설명한 뒤 현재 화면 정보를 요청한다.
- 사용자에게 API Key, Client Secret, Access Token, 비밀번호와 복구 코드를 채팅에 붙여 넣으라고 요청하지 않는다.
- 비밀값은 사용자가 공급자 UI, GitHub Secrets, 로컬 환경 변수 또는 합의된 비밀관리 서비스에 직접 입력하도록 안내한다.
- 사용자가 에이전트에게 알려줄 완료 신호는 `등록 완료`, secret 이름, 상태 화면 또는 마스킹된 메타데이터로 제한한다.
- 검증 출력에는 값 대신 `configured`, secret 이름 또는 마스킹된 메타데이터만 사용한다.
- 사용자의 완료 확인 전에는 해당 외부 설정이나 종속 기능을 완료로 표시하지 않는다.
- 사용자 개입으로 일부 작업이 막혀도 독립적으로 가능한 코드, 문서와 테스트 작업은 계속 진행한다.

## 대표적인 책임 분리

### Gemini

- `[AGENT]`: 모델 후보 비교, adapter와 Structured Output 스키마 구현, `GEMINI_API_KEY` placeholder와 테스트 준비
- `[USER]`: Google 프로젝트 선택, 결제·할당량 승인, API Key 생성과 실제 실행 환경/GitHub Secret 등록
- `[AGENT]`: 키 값 없이 등록 존재 여부와 연동 성공/실패를 검증하고 결과 보고

### Google·Kakao OAuth 2.0

- `[AGENT]`: 필요한 scope와 Redirect URI 후보 제시, 보안 설정·adapter·callback 코드와 테스트 준비
- `[USER]`: 개발자 콘솔 로그인, 동의 화면·앱 정보 승인, Client ID/Secret 발급, 실제 secret 등록
- `[AGENT]`: secret 값을 출력하지 않고 설정 존재 여부와 OAuth 흐름을 검증

### GitHub Actions Secrets

- `[AGENT]`: 필요한 secret 이름과 최소 권한을 정의하고 이를 참조하는 워크플로 작성
- `[USER]`: GitHub 저장소/Environment 설정에서 실제 secret 값 등록·회전·삭제
- `[AGENT]`: 워크플로가 올바른 secret 이름을 참조하는지와 실행 결과를 값 노출 없이 검증

### Grafana Cloud

- `[AGENT]`: Actuator·Micrometer 지표, JSON 로그, Alloy 설정, 대시보드·알림 규칙과 비밀값 없는 설정 placeholder 준비
- `[USER]`: Grafana Cloud 계정·stack과 요금제를 선택하고 telemetry 전송용 최소 권한 자격 증명 및 알림 연락 채널을 실제 환경에 직접 등록
- `[AGENT]`: 자격 증명 값을 출력하지 않고 지표·로그 수집 상태, 대시보드와 테스트 알림 결과를 검증
