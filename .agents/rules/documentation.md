# Documentation Rules

## 문서별 책임

- `docs/PRD.md`: 사용자가 원하는 제품 행동, MVP 범위, 비즈니스 규칙과 성공 지표
- `docs/ARCHITECTURE.md`: 시스템 구조, 기술 스택, 컴포넌트 책임, 데이터 흐름과 기술적 미정 사항
- `docs/ADR.md`: 차후 구현에 큰 영향을 주는 확정된 아키텍처 결정
- `.agents/rules/development.md`: 브랜치 전략, TDD, 코드 리뷰, 테스트·검증 및 개발 흐름
- `.agents/rules/api-documentation.md`: 프론트엔드가 사용하는 Swagger/OpenAPI 작성 규칙
- `.agents/rules/user-intervention.md`: 외부 계정·권한·결제·동의·비밀정보 작업의 사용자/에이전트 책임과 행동 가이드 규칙

## 변경 규칙

- 요구사항 변경은 PRD에, 기술 구조 변경은 Architecture에 반영한다.
- 한 결정이 여러 문서에 영향을 줄 때 각 문서의 책임에 해당하는 내용만 갱신하고 문장을 복제하지 않는다.
- 아직 합의하지 않은 선택은 `TBD`로 표시한다.
- 링크, 경로, 모델명과 임계값은 관련 기준 문서 사이에서 일치시킨다.
- 문서 날짜나 현재 지원 상태처럼 변할 수 있는 사실은 확인한 근거와 확인 시점을 함께 남긴다.

## 임시 산출물 수명주기

- 이슈별 설계·인계·실행 기록은 확장자와 접두사를 바꿔 새 문서나 이력 아카이브로 누적하지 않는다. `docs/**/ISSUE*.md`, `docs/**/issue*.md`, `docs/verification/issue*.json`, `docs/openapi/issue*.json`, `.tdd/history/`와 `_handoff/`에 새 임시 산출물을 추적하지 않는다. 현재 유효한 요구사항·설계·운영 규칙은 기존 기준 문서와 상시 운영 문서에 직접 반영한다. 재사용하는 평가 입력·스키마·현재 API 계약은 임시 실행 기록과 구분한다.
- `deploy/`에는 반복 사용하는 배포·런타임·복구·사전점검·검증 스크립트와 그 테스트·fixture만 둔다. 이슈 번호가 붙은 재사용 테스트나 과거 릴리스 호환 fixture를 일회성으로 간주하지 않는다.
- 임시 문서·진단·일회성 실행기·소스/테스트 before-image·인계 ZIP은 실제 소비자가 필요한 때만 생성한다. 단순 완료 보고를 위해 별도 파일을 만들지 않는다. 필요하면 Git에서 제외된 `.scratch/<work-item>/`, `.codex/tdd-evidence/<work-item>/` 또는 저장소 밖의 고유 임시 디렉터리를 사용한다. 실행기는 `TemporaryDirectory`나 `mktemp -d`와 종료 trap 등으로 자신이 만든 임시 자원만 성공·실패 후 정리한다. 검증과 인계가 끝나면 임시 요약·실행기도 삭제한다.
- RED·독립 검토·결함 주입의 짧은 근거는 `.agents/rules/development.md`에 따라 PR/리뷰에 남긴다. 전체 로그나 소스 사본을 새 추적 파일로 만들지 않는다. 반복 사용 도구가 필요한 경우 기존 도구에 통합하고 입력·출력·반복 호출 목적을 설명한다. 이미 추적된 운영 실패 기록이나 아직 필요한 원본 증거를 임의로 정리하지 않는다.
- 완료 보고 전에 `git status`와 hook 자체 테스트로 임시 산출물의 추적 혼입을 확인한다. 사용자 미추적 파일, 진행 중인 실패 증거·운영 로그, `.tdd`에 한시 보존 중인 후속 검증 증거는 이 정리 규칙을 근거로 삭제하지 않는다. 완료된 역사 기록은 정확한 Git revision에서 확인하며 현재 작업 트리에 복제하지 않는다. 새 임시 위치가 필요해도 해당 경로만 좁게 제외하고 JSON·스크립트·ZIP 전체를 숨기는 ignore는 추가하지 않는다.
