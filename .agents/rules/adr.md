# ADR Rules

## 기록 기준

ADR에는 차후 구현 방향, 시스템 경계, 데이터 호환성 또는 운영 구조에 큰 영향을 주고 되돌리는 비용이 높은 결정만 기록한다.

다음과 같은 결정은 ADR 대상이다.

- 애플리케이션 아키텍처와 모듈 경계
- 주 데이터베이스, 캐시와 데이터 소유권
- 인증·인가 모델
- 핵심 외부 서비스와 공급자 종속성
- 배포 토폴로지와 장기 운영 방식

다음과 같은 내용은 ADR 대상이 아니다.

- 브랜치 이름과 일상적인 Git 절차
- 코드 포맷, 네이밍과 사소한 구현 규칙
- 쉽게 교체할 수 있는 내부 유틸리티 선택
- 아직 합의되지 않은 후보 비교
- 단기 작업 상태나 TODO

## 작성 규칙

- 결정이 확정된 뒤 다음 순번으로 추가한다.
- 각 기록에는 `결정`, `이유`, `트레이드오프`를 포함한다.
- 미정인 내용은 `docs/ARCHITECTURE.md`의 후속 의사결정에 유지하고 ADR을 만들지 않는다.
- 기존 결정을 변경하면 이전 기록을 삭제하지 말고 새로운 ADR에서 대체 관계를 설명한다.
