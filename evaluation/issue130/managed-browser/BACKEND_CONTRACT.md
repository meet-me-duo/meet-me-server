## Validator result and safe error codes (before RED)

validate_manifest returns a new dict containing the original manifest fields and exactly four additional digests: manifestSha256/sourceSha256/runtimeSha256/classpathSha256. validate_readiness accepts that returned dict, checks exact readiness fields above, and returns {ready:true}. Errors are ValueError with exactly one of INVALID_MANIFEST, SOURCE_PIN_MISMATCH, RUNTIME_PIN_MISMATCH, CLASSPATH_PIN_MISMATCH, FORBIDDEN_FIXTURE_CLASS, MANAGED_GRAPH_REQUIRED, OUTBOUND_DENY_REQUIRED, SYNTHETIC_CREDENTIALS_REQUIRED, READINESS_PIN_MISMATCH. Malformed manifest/type/path/duplicate JSON keys or invalid fixed head goes INVALID_MANIFEST; malformed/mismatched source/runtime digest goes corresponding PIN_MISMATCH; unexpected CP or nonexistent/unlisted CP goes CLASSPATH_PIN_MISMATCH; unlisted file or prohibited fixture class goes FORBIDDEN_FIXTURE_CLASS when it is a .class, otherwise RUNTIME_PIN_MISMATCH. CLI malformed args emit {verified:false,error:INVALID_MANIFEST}, exit2 with no traceback. `--verify-only` success prints {verified:true,fixture,serverHead,policyOriginHead,manifestSha256,sourceSha256,runtimeSha256,classpathSha256}, no process start. Additional CLI `--readiness FILE --verify-only` validates the readiness JSON after pins and adds ready:true. Launch creates NEWDIR itself (runner must pass a nonexistent backend subdirectory). A manifest-generation compile step produces a sibling immutable source/ and runtime/ tree and manifest.json, then launch consumes only that snapshot, not live class directories.

For independent cleanup the backend work directory contains local-only 0600 `owned-resources.json`: {schemaVersion:1,containerIds:[disposablePG,disposableRedis],listenerPorts:[19440,19442,dynamicOIDC,dynamicSyntheticTLS],privateMaterialPaths:[ownedPrivateSubdirectory]}.
