# TDD 증거 수명주기

이 디렉터리는 증거 형식 스키마와 수명주기를 관리한다. 새 작업의 RED·독립 검토·결함
주입 결과를 별도 추적 JSON이나 소스 사본으로 누적하지 않는다. 기존 품질 게이트와
Red-Green-Refactor, 고위험 변경의 독립 검토·결함 주입 요건은 그대로 유지한다.

## 기록

1. 작업/TDD 주기 식별자, RED 전 기준 source revision, 실행한 테스트의 경로·SHA-256,
   실행 명령, 실패 테스트·예상 실패 분류·기록 시각을 PR 본문/리뷰에 간결하게 남긴다.
2. RED는 컴파일·준비가 성공하고 아직 없는 동작 때문에 예상 지점에서 실패해야 한다.
   전체 출력은 ignored `.codex/tdd-evidence/`에 두며 원문 로그·개인정보·비밀을 게시하지 않는다.
3. 검증 도구가 JSON을 실제 소비할 때만 같은 ignored 경로의 고유 작업 디렉터리에
   [RED 스키마](schema/red-evidence.schema.json) 또는
   [결함 주입 스키마](schema/fault-injection-evidence.schema.json)에 맞는 임시 파일을 만든다.
   단순 보고를 위한 파일이나 `.tdd/red/`, `history/`, `_handoff/` 사본은 생성하지 않는다.
4. 고위험 검증은 주입 결함·탐지 테스트·결과와 정확 복원한 source/test 지문 및 독립 검토를
   함께 기록한다. 과거 성공을 현재 source의 성공으로 재사용하지 않는다.

## 무효화와 정리

- 테스트 파일의 내용이 바뀌면 기존 요약은 무효다. 입력·기대값·논리가 같아도 지문이 바뀌면
  RED를 재확인한다. sourceRevision은 GREEN 커밋으로 임의 갱신하지 않는다.
- 현재 작업의 요약은 검증과 인계가 끝나면 삭제한다. 도구는 `TemporaryDirectory` 또는
  `mktemp -d`와 종료 trap 등으로 자신이 만든 임시 자원만 성공·실패 후 정리한다.
  아직 필요한 실패 근거·운영 원본·사용자 파일은 임의 삭제하지 않는다.
- 과거 근거는 정확한 Git revision에서 확인한다. 완료된 기록의 현재 트리 사본은 정리
  변경으로 제거할 수 있으며 원래 실행 결과·source/test 지문·Git 이력을 재작성하지 않는다.
- 새 작업이 JSON 파일 없이 PR/리뷰로 근거를 남겨도 명령·실패 이유·지문 대조와 최종
  품질 검사는 생략할 수 없다. 짧은 수명의 CI artifact만으로 장기 이력을 대체하지 않는다.

#190·#192 운영 복구/실패 기록 보존 요청과 연결된 기존 증거 3개는 이번 정리에서 보존한다.
#190의 원 운영 실패 복구 여부와 #192의 실패 기록 보존 의무가 종료됐는지 확인하기 전에는
지문을 고치거나 삭제하지 않는다. #197·#201 증거 13개는 각각 main 배포 run
41586238794·41751675850의 정확한 SHA와 최종 완료 검증 성공을 확인한 뒤 현재 트리에서
정리했다. 해당 구현/검토 근거는 병합 PR #198·#202와 정리 전 Git revision에 남아 있다.
정확한 기존 경로는 `.codex/hooks/tests/test_temporary_artifact_lifecycle.py`의
`RETAINED_EVIDENCE`에 한정돼 있다. 이 예외를 새 작업의 요약 생성 경로로 확대하지 않는다.

스키마의 FI 계약 검사용 예제는
`.codex/hooks/tests/fixtures/fault-injection-example.json`에 원래 바이트 그대로 유지한다.
과거 이슈 결과를 테스트의 현재 필수 경로로 삼지 않는다.
