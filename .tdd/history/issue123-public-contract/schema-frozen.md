# V17 schema proposal for independent fixture agreement

No SQL or production behavior implemented. Table/file names frozen by root; columns below await root review before READY fixture/DDL. V17 filename: `V17__add_durable_ai_room_budgets.sql`.

- `ai_room_budgets`: `room_id UUID PK/FK meeting_rooms ON DELETE CASCADE`; `state VARCHAR(32)` in UNCONFIGURED/HISTORICAL_UNKNOWN/UNTRACKED_EPOCH/READY/FROZEN; nullable `epoch_id UUID`, `unit_code VARCHAR(32)`, `unit_scale SMALLINT`, `cap NUMERIC(38,0)`, `policy_fingerprint VARCHAR(64)`, `coverage_started_at TIMESTAMPTZ`; `settled NUMERIC(38,0) NOT NULL DEFAULT 0`, `held NUMERIC(38,0) NOT NULL DEFAULT 0`, `version BIGINT NOT NULL DEFAULT 1`. Positive configured cap and nonnegative aggregates; complete READY metadata required. `snapshot` maps these names directly to frozen public DTO. No row for absent/deleted room. Historical migration inserts HISTORICAL_UNKNOWN with cap/unit/epoch/policy/coverage NULL, not READY/spent-zero authority.
- `ai_budget_profiles`: globally reusable **non-PII structural metadata only**. `profile_snapshot_fingerprint VARCHAR(64) PK` is SHA256 of canonical structural `profile_fingerprint`, `policy_fingerprint`, `unit_code`, `unit_scale`; these four fields are NOT NULL and exclude per-input/request data. The quote port's `evidenceFingerprint` is conservatively kept only on the room reservation because it is not typed as global structural evidence. No whole payload/source/context/room/execution hash, payload-derived quote hash, quote amount or request ID exists here. Same snapshot hash with changed structural fields conflicts, never UPDATE. No seed live profile or activation. The registry remains authority for the actual immutable quote; this table does not infer permission from a global row.
- `ai_call_reservations`: `id UUID PK`; `room_id UUID FK ai_room_budgets ON DELETE CASCADE`; `execution_kind`, `execution_id UUID`, `generation BIGINT`, `execution_version BIGINT`, `owner_token UUID`, `source_fingerprint`, `context_fingerprint`, `operation`, `ordinal INTEGER`, nullable `attempt_id UUID`; `profile_snapshot_fingerprint FK ai_budget_profiles`; room-owned immutable `quote_fingerprint`, `whole_payload_fingerprint`, `profile_fingerprint`, `policy_fingerprint`, `evidence_fingerprint` VARCHAR(64), `maximum_amount NUMERIC(38,0)`, `unit_code VARCHAR(32)`, `unit_scale SMALLINT`, `quote_valid_until TIMESTAMPTZ`; `epoch_id UUID`; `state` in RESERVED/DISPATCH_INTENT/UNKNOWN/SETTLED; `hold_amount NUMERIC(38,0)`; nullable `dispatch_token UUID UNIQUE`, `dispatched_at TIMESTAMPTZ`, `dispatch_deadline_at TIMESTAMPTZ`, `lease_until TIMESTAMPTZ`, `settled_amount NUMERIC(38,0)`, `settled_evidence_fingerprint VARCHAR(64)`; `reserved_at`, `updated_at` TIMESTAMPTZ. Unique physical identity `(room_id,execution_kind,execution_id,generation,operation,ordinal)`; source/context/profile/version/owner mismatch on this identity is conflict, not a new reservation. Final attempt IDs/provider ordinal validated against existing rows by fence; precheck final IDs cannot be mixed. Lease never authorizes intent replay/refund. Every payload-specific quote/fingerprint/amount is confined to this room-owned cascade row. No raw text is stored; execution identifiers remain internal. Do not FK to coordination_attempts/submission rows in a way that restricts existing retention order; authoritative attempt binding is checked by the fence.
- `ai_call_observations`: `reservation_id UUID FK ai_call_reservations ON DELETE CASCADE`; `event_key VARCHAR(128)` and `event_fingerprint VARCHAR(64)`; `kind` USAGE/BILL; nullable `outcome`,`failure`,`input_tokens`,`output_tokens`,`reasoning_tokens`,`cached_input_tokens`; `usage_complete BOOLEAN NOT NULL DEFAULT false`; nullable `bill_amount NUMERIC(38,0)`,`evidence_fingerprint VARCHAR(64)`; `created_at TIMESTAMPTZ`; PK `(reservation_id,event_key)`. USAGE event_key=eventId; BILL event_key is fixed canonical trusted receipt identity, distinct namespace. Nullable counters never become zero; complete-bill evidence remains distinct from usageComplete.

READY fixture seam (test-owned only): after V17 migration creates HISTORICAL_UNKNOWN for an existing V16 room, an explicit synthetic fixture UPDATE sets state READY, epoch_id/test-policy-fingerprint/unit-code/test-unit-scale/cap/coverage_started_at, with settled=held=0. This is synthetic proof setup, not historical cost inference or a production activation method. Fake fence returns that epoch and an effective deadline; fake trusted registry returns complete immutable quote/bill evidence. Production resolver defaults DENY. No test DDL substitutes for V17 or counts missing schema/setup failures as RED.

V17 first seeds pre-existing rooms HISTORICAL_UNKNOWN, then installs an AFTER INSERT ON meeting_rooms trigger (`trg_init_ai_room_budget`, function `initialize_ai_room_budget`) inserting UNCONFIGURED with null policy/unit/cap/epoch/coverage and zero non-authoritative counters. This makes every new room row+unconfigured budget creation one transaction, including direct SQL fixtures, with no room repository/provider edit and no request-time lazy bootstrap. Snapshot of an existing room lacking a budget row is null/DENY; missing room is null; reserve/claim/observe/settle cannot recreate deleted room rows. Parent retains current30day room deletion + cascade. Global profile rows are strictly structural metadata with no room/request-derived content; all request-specific quote/evidence/usage resides only in room-owned cascade rows. Orphan structural-profile cleanup is not financial UNKNOWN refund or retention of input hashes.

Format bounds are technical, not live monetary choices: scale must be explicit nonnegative and within selected BigInteger persistence precision; amount over numeric(38,0), invalid/blank unit/fingerprint, unconfigured cap or missing evidence fails closed. Actual currency/scale/amount/price remains absent in production.
